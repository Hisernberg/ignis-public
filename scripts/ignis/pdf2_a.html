Executive Summary

IGNIS unifies 25 years of MODIS and VIIRS active-fire detections into one harmonized calendar, adds live early warning and a 12-month seasonal outlook, and runs entirely on authentic NASA APIs plus an on-device Hugging Face model. This dossier is the operating manual for the win: the architecture is finalized, every portion has been built and verified (8 regional calendars, ~9,000 sampled months, 758 live detections rendered), deployment takes 15 minutes on Vercel, and a chat-executable runbook allows any AI assistant to continue the pipeline. Target: Global Awards, Challenge 09.

01The Product, Portion by Portion

Six portions, each independently shippable — the first five are already live in the repo.

P1 · Live Fire Map DONE

GIBS MODIS Terra true-color raster basemap (any day) under three sensor-colored detection layers sized by FRP, drawn from /api/hotspots. FIRMS area API is primary; GIBS vector tiles are the automatic fallback. AOI presets for 8 regions plus click-to-pick custom boxes; date picker back to 2000-11.

P2 · Harmonized Calendar DONE

Year × month heatmaps per sensor from 2000 to present plus a trend-line view, from /api/calendar. Amazon peaks every Aug–Oct; NOAA-20 rows honestly empty pre-2020 — the sensor break made visible, then unified by the continuity coefficient.

P3 · Sensor Harmonization Panel DONE

Per-sensor counts, mean FRP, high-confidence share, per-sensor data latency, measured SNPP/MODIS ratio (12.1×–29.2× across regions), and top 0.25° fire clusters. This is the intellectual core the challenge rewards.

P4 · Early Warning & Triage DONE

Rule engine on live detections sets GREEN/AMBER/ORANGE/RED with reasons; EONET open wildfire events ranked per-AOI by an on-device Hugging Face MiniLM embedding model with geo + semantic fusion scores.

P5 · Seasonal Outlook DONE

12-month forecast with log-normal uncertainty band from the fused harmonized record; verified peaks match climatology (Amazon Sep, Canada Jul, Australia Nov). Chronos-Bolt swappable per runbook.

P6 · Event-Weekend Polish WEEKEND

Vercel deploy (runbook Phase 5), pitch recording, Hugging Face model-card upload, submission form. Capped at ~90 minutes because everything above is pre-built.

02Architecture — API-First, MCP-Ready

One Next.js 16 app; every capability is an HTTP endpoint, so automation and judges can consume the same surface.

EndpointServesData path
GET /api/hotspotsGeoJSON detections per sensor for bbox + dayFIRMS area API (MAP_KEY) → fallback GIBS WMTS MVT (gzip-decoded, full FIRMS schema); 10-min cache

Resilience design

  • Dual-source hotspots: FIRMS primary, GIBS fallback — verified live when the sandbox firewall blocked FIRMS; the app never shows an empty map.
  • Precomputed heavy paths: the 25-year calendar ships as static JSON (~2.9 MB total), making the demo immune to archive latency or API quota surprises.
  • Honest telemetry: per-sensor "latest available" labels (e.g., GIBS SNPP archive ends 2026-07) and a status rail expose system truth — a trust signal judges notice.

Secrets & automation surface

All credentials live in secrets/.env inside the private repo (FIRMS MAP_KEY, elevated NASA key, EDL JWT for CMR/ASF, HF token, EDL credentials) with a sanitized .env.example. The repo mirrors the app, the precompute scripts, eight calendar/outlook JSONs, both dossiers and the chat-executable runbook — the complete operating system for the project. An optional MCP server (runbook Phase 8) wraps the five endpoints as tools (get_hotspots, get_calendar, get_outlook, get_health), making the whole pipeline machine-drivable from any MCP client.

Why MCP matters for judging: it converts the project from "an app" into "an API-automated capability" — the exact construction style the team's constraint set demands, demonstrated live in 30 seconds by querying a tool mid-pitch.

Defects found and fixed during verification

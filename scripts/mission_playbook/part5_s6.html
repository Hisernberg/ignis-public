SECTION 06 // THE FLAGSHIP
TERRA SENTINEL — Mission Control for Planet Earth

The one app you will build: a live Earth-event intelligence platform fusing NASA’s open data with an AI analysis stack, engineered to be defensible in every award category.

TERRA SENTINEL is a web platform that watches the planet the way mission control watches a spacecraft. It ingests NASA’s live natural-event feed and satellite imagery, fuses them with forecast and segmentation models, and turns the noise into plain-language mission briefings anyone can act on. The one-line pitch: “Mission control for planet Earth — live events, satellite eyes, and an AI analyst that explains what is happening anywhere on the planet, right now.” It is built on the three streams judges can verify in seconds — EONET, GIBS, FIRMS — and it is deliberately architected so that disaster, climate, air-quality, and even space-weather challenges are skins over the same chassis.

6.1 The Five Core Features
FEATURE 01 // LIVE OPS MAP
The planet, breathing
A MapLibre globe with EONET events pulsing live — wildfires, storms, volcanoes, ice — over a GIBS true-color layer from today. FIRMS hotspots render as a GPU heatmap via deck.gl. Fly-to animation takes you inside any event in one click.
FEATURE 02 // AI MISSION BRIEFER
From raw feed to briefing
Select an event; the platform assembles structured context (location, area, population in buffer via Shapely, satellite layer, forecast curve) and an LLM writes a numbered field briefing with confidence levels and dataset citations. Human-readable in 90 languages via the UI layer.
FEATURE 03 // PREDICTIVE TIMELINE
What happens next 72 hours
Chronos-Bolt zero-shot forecasts fire-count or AQI time series for the region, plotted against the observed history with a confidence band and one honest validation metric (MAE vs. persistence) printed under the chart.
FEATURE 04 // SATELLITE VISION
The satellite’s eye, quantified
Pull the event window’s imagery; SAM segments water or burn scars with a click, and the platform computes affected area in hectares and population intersected — the measurement that turns a picture into a number a judge can trust.
FEATURE 05 // STORY MODE
The replay judges remember
A cinematic guided sequence: EPIC full-disc Earth, then a zoom from orbit into the event region across the last 30 days of GIBS imagery, narrated by the AI briefer. This is the screenshot moment from Pattern 06 — protected at all costs.
FOUNDATION // PRE-WIRED
Prithvi-EO embeddings
The Prithvi-EO-2.0 Space is pre-wired in prep week and offered as the science extension — land-cover context under events or burn-scar classification. It ships wired but is the first feature dropped under the triage ladder if time compresses.
6.2 System Architecture

Four layers make up the platform, each replaceable without touching the others: the NASA data layer feeds Python pipeline workers, which persist clean, geometry-enriched event records to PostGIS; HF Spaces microservices read that same database to produce forecasts, segmentations, and briefings; and the Next.js experience layer renders it all as mission control. Because every layer degrades gracefully to the one below it, a cold model Space or a stalled fetcher never blanks the screen — the demo path survives every individual failure.

The architecture obeys one hackathon law on top of this layering: the demo path never crosses a fragile dependency. If a model Space is cold or down, the Event Console still renders the briefing shell from the pipeline database; if the pipeline stalls, the map still shows live EONET fetched client-side. Every layer degrades gracefully to the layer below it, and the recorded video covers the worst case entirely.
